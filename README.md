# elanfp-0c4b — открытый драйвер сканера отпечатков ELAN 04f3:0c4b

[![ci](https://github.com/Redox-openDriver/elanfp-0c4b/actions/workflows/ci.yml/badge.svg)](https://github.com/Redox-openDriver/elanfp-0c4b/actions/workflows/ci.yml)
[![license](https://img.shields.io/badge/license-AGPL--3.0--or--later-blue)](LICENSE)

An open driver for the ELAN 04f3:0c4b fingerprint reader (80×80 image sensor, matching on the host) for Linux and
Redox OS: guided enrollment, verification with adaptation, encrypted templates with the key in the TPM, PAM for `sudo`
and login, and a drop-in replacement for fprintd's D-Bus interface so desktop fingerprint settings work. It runs only
with the exact sensor variant it was verified on. The documentation below is in Russian.

Вход и подтверждение `sudo` отпечатком пальца на ноутбуках со сканером **ELAN 04f3:0c4b** — без закрытых библиотек.
Программы и служба называются `elanfp`.
Статус: **бета** на Linux, на Redox OS — рабочая служба и клиент, проверенные в QEMU на настоящем сканере.

> Независимый открытый проект. Не связан с ELAN Microelectronics; название ELAN указано только для обозначения совместимого устройства.

## Устройство
| | |
|---|---|
| USB | `04f3:0c4b`, «ELAN:Fingerprint», встроенный порт |
| Сенсор | 80×80, ёмкостный, сравнение на компьютере (не match-on-chip) |
| Проверенная прошивка | 26.30 |
| Ноутбук | Lenovo ThinkBook 16 G6 ABP (21KK) |

Драйвер работает только с проверенным вариантом сенсора (прошивка, поколение чипа, размер матрицы) на порту, который
прошивка компьютера описывает как внутренний. Другой вариант или порт — понятная ошибка, а не попытка «как-нибудь заработать».
Другие модели сканеров ELAN и другие устройства ELAN (тачпады и т. п.) этот драйвер не поддерживает: для них будут
отдельные репозитории в [Redox-openDriver](https://github.com/Redox-openDriver).

## Что умеет
- регистрация пальца с подсказками: заканчивается сама, когда набралось достаточно подтверждающих друг друга касаний;
  то, что от касания к касанию остаётся на месте (грязь, плёнка, след на сканере), ничего не весит ни при регистрации,
  ни при проверке, а регистрация поверх такого неподвижного рисунка останавливается с объяснением;
- проверка касания, две попытки, дообучение на уверенных совпадениях с исходной регистрацией;
- отбраковка плохих кадров: частичное касание, мокрый палец, движение;
- шаблоны только зашифрованные; ключ в TPM там, где это возможно;
- `sudo`, вход и блокировщики через PAM; настройки отпечатков рабочих столов (KDE, GNOME и другие) через тот же
  интерфейс D-Bus, что у fprintd;
- уведомление на рабочем столе, когда отпечаток просит программа с правами root: какая служба PAM спрашивает и как
  программа себя называет;
- пароль остаётся всегда: не узнал, занято или сбой — обычный пароль; 5 неудач подряд — 10 минут только пароль,
  каждая следующая блокировка вдвое дольше; снять её раньше: `sudo elanfp unlock`.

## Установка (Linux)
Нужен Rust (`cargo`); библиотеки papilla и drv-i18n cargo при сборке скачает сам. Установщик запускается от своей
учётной записи, права root он попросит через `sudo` или `doas`.
```sh
git clone https://github.com/Redox-openDriver/elanfp-0c4b
cd elanfp-0c4b
linux/dist/install.sh
sudo elanfp enroll right-index-finger
elanfp verify
```
Установщик сам определяет менеджер служб и ставит родное для него описание службы:

| Окружение | Что делает установщик |
|---|---|
| systemd | юнит с песочницей, ключ запечатан в TPM (`systemd-creds`), без TPM — файл ключа |
| OpenRC, runit, dinit | служба под надзором менеджера от пользователя `elanfp`, ключ — файл службы |
| s6 | кладёт описание службы и говорит, как включить |
| менеджер не распознан | ставит программы и говорит, как запустить службу вручную |
| sudo или doas, glibc или musl, udev или eudev | поддерживаются; без udev доступ к устройству настраивается вручную |

В конце установщик печатает, чем защищён ключ и зашифрован ли диск. Переменные: `ELANFP_SERVICE_MANAGER` (выбрать менеджер
вручную), `ELANFP_TPM2_PCRS=7` (привязать ключ к состоянию загрузки — только при первой установке, пока ключа нет;
существующий ключ установщик не меняет и не затирает), `ELANFP_FPRINTD_BRIDGE=no` (не ставить мост, а поставленный
раньше — убрать).

Удаление: `linux/dist/uninstall.sh` (шаблоны остаются; `--purge` — удалить и их, и ключ, и учётные записи;
`--bridge` — убрать только мост).

### sudo, вход, блокировщик экрана
Первая строка `auth` в `/etc/pam.d/sudo` (так же — для `doas`, блокировщика, экрана входа):
```
auth sufficient /usr/local/lib/security/pam_elanfp.so
```
Держи открытым второй терминал с root, пока не убедишься, что `sudo` работает. Параметры модуля: `timeout=10`
(сколько секунд ждать касания), `console=any` (не проверять, кто за консолью — только там, где нет logind и нет
удалённого входа).

Не ставь модуль в общие стеки вроде `system-auth` и в `su`: отпечаток подтверждает того, кто сидит за ноутбуком, а эти
стеки проверяют и чужие учётные записи. Модуль сам откажет, если его вызвал не проверяемый пользователь и не root.
Штатный `pam_fprintd` (через мост, см. ниже) такой проверки не делает вовсе — для него это правило обязательно.

### Настройки рабочего стола
Установщик ставит мост `elanfp-fprintd`: он занимает имя `net.reactivated.Fprint` вместо fprintd, который этот сканер
не поддерживает (сам пакет fprintd остаётся, но занять это имя он больше не может, пока мост установлен; установщик это проверяет и
предупреждает, если правила D-Bus на машине всё же оставляют имя доступным root). После этого
страница отпечатков в настройках рабочего стола, `fprintd-enroll`, `fprintd-verify`, `fprintd-list` и штатный
`pam_fprintd` работают с этим драйвером. Мосту нужен polkit: без него он отвечает только root (то есть `pam_fprintd` в
`sudo` и на экране входа), а `ELANFP_FPRINTD_POLKIT=off` в окружении моста разрешает без polkit лишь проверку своего
пальца. Регистрация из окна настроек спрашивает твой пароль, чужая учётная запись —
пароль администратора. Пальцы называются стандартно: `right-index-finger`, `left-thumb` и так далее. Индикатор
регистрации рассчитан на 120 касаний — столько она занимает в худшем случае; обычно заканчивается раньше.

### Кто просит отпечаток
Установщик ставит в автозапуск сеанса `elanfp-notify`. Когда отпечаток твоей учётной записи запрашивает программа с
правами root (`sudo`, экран входа, агент polkit) или для неё регистрируют палец, на рабочем столе появляется уведомление
и исчезает, когда запрос закончился. В нём названа служба PAM, через которую пришёл запрос (`sudo`, `polkit-1`…): её
сообщает `pam_elanfp`, и подделать её программа без прав root не может. Командная строка показана последней, в кавычках,
как слова самой программы — их выбирает тот, кто её запустил, — и только её начало; у запросов через мост (штатный
`pam_fprintd`, окна настроек) нет ни того, ни другого, сказано лишь, что запрос пришёл через мост.
Запросы самого пользователя (экран блокировки) уведомлений не дают. В сеансах без автозапуска XDG запусти
`elanfp-notify` сам (второй экземпляр в том же сеансе сразу выходит); `ELANFP_NOTIFY=no` при установке его не ставит.
Это подсказка, а не преграда: программа под твоей же учётной записью может уведомление закрыть.

### Журнал
`journalctl -u elanfpd` показывает, кто и когда регистрировал, удалял и проверял пальцы. Оценки сравнения и динамика
касаний пишутся только с `ELANFP_DIAGNOSTICS=on` в окружении службы: системный журнал читают не только root.

## Устройство кода
| часть | что делает |
|---|---|
| `core` | протокол сенсора, проверка качества кадра, привязка к варианту сенсора (`no_std`) |
| `engine` | касание, регистрация, проверка, хранилище, служба с правами и блокировками, сообщения — общее для всех ОС |
| `ipc` | протокол между службой и клиентами (только стандартная библиотека) |
| `linux` | транспорт `nusb`, ключи, служба `elanfpd`, клиент `elanfp`, установщик; для разработки — `elanfp-dev` (прямой доступ к сенсору) и `elanfp-dataset`, они не устанавливаются |
| `pam` | `pam_elanfp.so` |
| `fprint` | мост `elanfp-fprintd` для рабочих столов |
| `notify` | `elanfp-notify`: уведомление в сеансе о запросах отпечатка от программ с правами root |
| `redox` | транспорт через `xhcid`, служба-схема, клиент, рецепт — см. [redox/README.md](redox/README.md) |
| [`papilla`](https://github.com/Redox-openDriver/papilla) | распознавание и шифрование — общая библиотека для всех сканеров |
| [`drv-i18n`](https://github.com/Redox-openDriver/drv-i18n) | сообщения: весь текст для человека лежит в `locales/*.ftl` |

Транспорт сообщает, умеет ли он прервать ожидание по таймауту. Там, где не умеет (USB-стек Redox), движок сам
переходит на опрос кадрами — без условий «если Redox» в логике драйвера.

## Проверка
| команда | что проверяет |
|---|---|
| `cargo test --release` | все наборы тестов на имитаторе сенсора; мост — на отдельной шине D-Bus с поддельными polkit, logind и службой (нужен `dbus-daemon`) |
| `scripts/portability/alpine.sh` | musl без systemd: тесты, установщик под OpenRC, runit, dinit, s6 и без менеджера, PAM, мост |
| `scripts/redox-test.sh` | те же тесты и служба-схема внутри Redox в QEMU |
| `scripts/redox-hw.sh` | настоящий сканер, проброшенный в Redox |
| `elanfp-dataset replay` | записанные сессии через рабочий конвейер: регистрация, свои и чужие касания (запускается из каталога, где лежит `captures/` с записями; записи в репозиторий не входят) |
| `elanfp-dataset stained 30` | то же с «загрязнённым сканером»: в каждый кадр подмешан один и тот же чужой кадр с заданным весом |
